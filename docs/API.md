# API contract

All application routes begin with `/api`. Except bootstrap/login and Meta webhooks, requests require a server-side session. Reads and writes are scoped to its current workspace; backend-wide schedulers and the signed pre-workspace inbox are service operations, not customer APIs. Sessions select the user's existing workspace; this release provisions one workspace per deployment and creates new members inside it, rather than exposing multi-workspace switching.

Responses are `{ "ok": true, "data": ... }` or `{ "ok": false, "error": { "code", "message", "requestId" } }`. CSV and successful OAuth redirects are exceptions. HTTP statuses include 400 validation, 401 authentication, 403 permission/CSRF/origin, 404 absent-or-out-of-workspace resource, 409 conflict, 413 size, 415 content type, 429 limit, and 503 missing configuration/transient Meta failure. Unknown failures never echo SQL, token values, request payloads or external response bodies.

Every JSON write requires `Content-Type: application/json`, an explicitly allowed `Origin`, and `X-CSRF-Token` from login or `/auth/me`. The frontend keeps this token only in memory; the authentication cookie is HttpOnly. Login/bootstrap are protected by origin/JSON checks and rate limits instead of a pre-login CSRF token. Webhook POST uses raw-body HMAC instead of browser CSRF. `GET /meta/connect` and the form-refresh GET also require CSRF because they initiate server state changes.

## Lead filters and sorting

`q`, `status`, `form` (external form ID), `pageId`, `assignedTo`, `source`, `from`, `to`, `sort`, `page`, `pageSize`. Text search covers name/email/phone/campaign/form/Page and external lead ID. Literal `%`, `_` and backslash are escaped. D1 limits LIKE patterns to 50 UTF-8 bytes, so overly long searches return a validation error asking for a shorter fragment. SQL sort keys are whitelisted: `newest`, `oldest`, `name`. Default page size is 25, maximum 100, stable secondary ID ordering. Offset pagination supports this single-owner scale; concurrent incoming records can shift page boundaries.

UTC `from`/`to` dates are real `YYYY-MM-DD` dates and inclusive; implementation uses an exclusive next-day upper bound. Dashboard/analytics default to the last 30 UTC calendar days and accept the same filters. Total/converted figures refer to that range, not a mixture of all-time and recent data. Follow-ups due uses current UTC time across the whole workspace. `dueAt` must be an explicit ISO timestamp including timezone. Notes, statuses, assignment and task completion are never overwritten by a historical import.

The five initial stages are shared through `shared/contracts.ts` and enforced by SQL. Future custom stages require a versioned schema/API/UI change; this release does not expose unvalidated arbitrary stage names.
