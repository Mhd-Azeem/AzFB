# Security and operations notes

This is an implemented application with local tests, not an assertion of completed production security review or verified Meta delivery. Complete the external checklist in DEPLOYMENT.md before processing customer data.

## Controls

- One-time secret-protected atomic Owner provisioning. No default production account or password. Remove the bootstrap secret afterward.
- Salted PBKDF2-SHA256 with 100,000 iterations and an HMAC server pepper, using Workers Web Crypto. Workers caps PBKDF2 at this count; this is a platform-constrained choice, not a claim that it meets every current password-hashing recommendation. Protect the pepper as an independent server secret from D1 and load-test on the selected plan.
- Random 256-bit session tokens stored as SHA-256 hashes. Production `__Host-` cookies use Secure, HttpOnly, SameSite=Lax, Path=/ and no Domain. One-hour inactivity deadline, 8-hour absolute deadline; visible-tab 15-minute rotation does not extend the absolute deadline. A 30-second old-token grace window prevents in-flight reads from failing during renewal. Logout revokes the entire current session family, including grace tokens; password changes revoke all sessions. There is no MFA/password-reset email service in this release.
- D1-atomic per-IP and account login limits. Five failed account attempts lock further attempts for the remaining 15-minute window; successful authentication clears that account's failed-attempt counter. An additional 20-attempt IP window and authenticated write limits reduce abuse. Expired limiter keys are cleaned by Cron. These are application limits, not an assertion of DDoS immunity; deploy platform abuse controls if needed.
- Exact-origin allowlist plus Origin-required JSON writes and session-specific CSRF headers. The OAuth callback validates a random, hashed, 10-minute, session-family/workspace-bound, one-use state. GET connect/form refresh also require CSRF. Cross-site OAuth returns use SameSite=Lax; callback sessions cannot be switched by state from a different browser session.
- Explicit Owner/Admin/Agent permissions, validated fields, workspace-scoped reads/writes/exports, composite foreign keys for cross-record ownership, and parameterized SQL. Agents can see workspace leads but cannot manage connections, assignments, retention, membership or deletion; they can edit their own assigned tasks. Workspace visibility is deliberate team behavior, not per-agent record confidentiality.
- AES-256-GCM token storage with random 96-bit IVs and authenticated workspace/Page context. A token ciphertext from one Page/workspace cannot be decrypted in another context. Meta app secrets, Page/user tokens and credentials never appear in frontend variables/storage or API payloads. Token exchange necessarily sends credentials to Meta's official endpoint, but URLs/bodies are not logged by application code.
- Exact raw request bytes authenticated with HMAC-SHA256 and `X-Hub-Signature-256` before parsing. Requests are capped at 256 KiB. Unknown Pages, unselected forms and malformed event entries never create customer leads. The signed service inbox is resolved into workspace-owned records by trusted background code and is not exposed by APIs.
- App/Page subscription confirmation, token app-ID/expiry/scopes checks, safe Graph host/path construction, only Graph cursors reused (never untrusted `paging.next` URLs), fetch timeouts, delayed retry and durable jobs/leases. Optional metadata permissions failures fall back to the basic lead fields; a basic retrieval permission failure is not silently ignored.
- Meta's external submission ID plus workspace and Page uniquely identify a submission. Email/phone similarities only produce a possible-repeat hint. Answers are normalized without a fixed question schema, and raw normalized field data is retained. Oversized/invalid answer sets fail explicitly with an operational diagnostic rather than silently truncating submitted answers.
- Spreadsheet formula protection includes leading whitespace; CSV quotes/separators/newlines are escaped. Exports are bounded and match the server-side filters.
- CSP, HSTS in production, frame denial, no-referrer, MIME protection, no-store API responses and safe React text rendering. Inline styles remain permitted for chart sizing; scripts do not use unsafe-inline. Public fonts are fetched from Google Fonts with system fallbacks, which can be removed for a no-third-party-resource deployment.
- Minimal audit events record actor IDs, action, target ID and time, not note contents, passwords or tokens. Unexpected error logs contain a request ID/event only. No raw customer payloads or Meta response bodies are logged.

## Recovery and data handling

`sync_jobs` is the durable application dead-letter/replay store; Queues is optional transport. Fix Page authorization, reselect/reconnect as needed, then replay the failed job. A successful retry cannot replace stages, notes, assignment or tasks. Checkpoints are advanced only after a historical page chain succeeds. Reconciliation overlaps its previous successful checkpoint by 48 hours and uses time-created filtering. Manual Sync Now performs a fresh available-history scan for completed jobs, or resumes active jobs; dead jobs require explicit replay.

Jobs use a 180-second lease; signed inbox dispatch uses a 120-second lease. Interrupted work is reclaimable. Normal job retries use exponential backoff, jitter and Retry-After (bounded to six hours), and stop after eight consecutive failures for a page. Permission/token errors stop immediately. Re-import progress increments in the same D1 batch as each newly inserted lead, so a partially failed page still records successful inserts. Scheduled work is bounded for the Free-plan per-invocation D1 limit. Without Queues, delivery/history throughput is intentionally low; do not promise real-time ingestion or arbitrary volume.

Owner retention is measured from original submission time; the default is 365 days. A scheduled invocation deletes at most two expired submissions, cascading notes/answers/tasks, and stores minimal external-ID suppression tombstones to prevent re-import. This bounded default may take time to drain a large deletion backlog. Manual Admin deletion is immediate in the active database. Completed raw-metadata inbox/events expire after seven days; completed/cancelled jobs after 30 days. Dead jobs/audit history are retained for diagnosis. These policies do not erase provider-controlled backups immediately; review Cloudflare backup/Time Travel retention and your privacy policy. Tombstones retain external IDs only and require an intentional migration/maintenance policy to remove.

For a person's access request, identify all matching submissions, inspect repeat-contact hints, and export using the authorized filters. For deletion, review/delete each relevant submission and any unlinked tasks containing their information. Do not put secrets or unnecessary sensitive information in notes/task titles. Team member access can be disabled by the Owner, which revokes their sessions. There is no anonymous customer-data access endpoint.

Disconnect erases local Meta credentials even if the remote revocation request fails, stops selected-form processing, and preserves saved CRM records. If revocation cannot be confirmed, the UI asks the owner to remove the app in Facebook Business Integrations. Reconnecting discovers Pages again and requires Page selection. Do not confuse a confirmed subscription with proof of a real lead round trip.

## Remaining external verification

Real Cloudflare quotas/latency and operational monitoring, production HTTPS cookies and custom domain configuration, Meta app eligibility/App Review/lead access, real signed delivery, real Graph retrieval, remote migration/backups, multi-device sessions and account recovery procedure must be validated by the owner. Tests mock Meta's external service. No vulnerability-free or production-ready claim follows from those tests alone.
